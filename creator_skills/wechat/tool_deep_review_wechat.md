# 公众号·AI 工具深度实测 Skill（写作骨架）

---

## 写作哲学（每次生成前必须内化）

这不是产品手册，也不是功能评测。

这是**一个真实的人，替读者走了一遍从陌生到上手的路**，然后回来告诉你：这条路值不值得走、走的时候会卡在哪、走完之后你会得到什么。

读者读完应该有三样东西：
1. **一个决定**：这个工具值不值得我花时间试
2. **一个框架**：这类工具我以后怎么判断
3. **一个动作**：今天我可以做的一件具体的事

如果生成的内容读起来像技术文档、像功能列表、像产品介绍页，说明这篇文章失败了。

---

## 写前必须完成的资料采集（搜索策略）

**在生成正文之前，告诉作者需要搜索以下内容，没有这些信息，正文会空洞：**

### 第一类：事实骨架（必须核验，不能编造）
- `[工具名] official site` → 官方入口、下载链接、定价页
- `[工具名] docs getting started` → 官方入门文档
- `[工具名] pricing 2026 free tier` → 当前真实价格和免费额度
- `[工具名] system requirements` → 支持哪些系统

### 第二类：真实用户体验（最有价值的素材来源）
- `[工具名] site:reddit.com` → 英文用户真实吐槽和好评
- `[工具名] site:v2ex.com` 或 `[工具名] 知乎 真实体验` → 国内用户反馈
- `[工具名] honest review 2026` → 非官方评测
- `[工具名] 国内 使用 网络` → 国内用户特有的障碍

### 第三类：真实痛点（让文章有深度的关键）
- `[工具名] not working common issues` → 新手最常卡的地方
- `[工具名] setup problems beginners` → 安装阶段的实际障碍
- `[工具名] limitations what it can't do` → 工具做不到的事

### 第四类：定位判断（让读者做决策）
- `[工具名] vs [竞品]` → 和已知工具的核心差异
- `[工具名] alternatives` → 同类选项
- `[工具名] use case examples` → 真实使用场景，不是官方宣传场景

### 搜索后做一件事
把采集到的内容分成两列：
- **我确认是真的**（来自官方或多个独立来源）
- **我没法核验的**（只标注"待核验"，不编造）

这个分类直接决定文章哪些部分可以写细、哪些要加"建议你自己核验"。

## 五幕叙事结构

> 注意：这是**写作骨架**，不要把"第一幕""第二幕"写进正文标题。正文标题用自然语言。

---

### 第一幕：我为什么在乎这个（150-200 字）

**唯一目的**：让读者在前三行认出自己的处境。

**格式**：
- 第一句：我当时在做什么（具体到一个动作，不是"我在学AI"，而是"我在整理一个看不懂结构的项目"）
- 第二句：我遇到了什么具体障碍（不是"效率低"，而是"我不知道从哪个文件开始看"）
- 第三句：我为什么选择试这个工具（不是"它很热门"，而是"有人在群里说它能先解释再改，不会乱动你的代码"）

**禁止**：
- 不能从工具介绍开始（"[工具名]是一款……"这种格式直接违规）
- 不能写"很多人都会遇到……"，只写"我遇到了……"
- 不能写市场背景、行业趋势

**示例**（可参考语感，不要原样复制）：
> 上周我在整理一个别人给我的项目，文件夹里有二十几个文件，我完全不知道该从哪里下手。我不想直接把代码丢给 AI 改，因为我怕它直接动了我看不懂的东西。然后有人在群里提到 [工具名]，说它能先解释结构，再问你要不要改，这让我决定试一下。

---

### 第二幕：在你下载之前，先做这个判断（200-300 字）

**唯一目的**：帮读者在 3 分钟内决定值不值得继续读。

**格式**：
```
【适合你，如果你……】
- 场景 1：具体的，带动词（比如"你经常需要整理别人的项目"）
- 场景 2：具体的
- 场景 3：具体的

【暂时不适合，如果你……】
- 限制 1：具体说明是什么限制（系统/网络/付费/技术门槛）
- 限制 2
- 不要超过 3 条，不要写废话

【下载前先确认】
- 官方入口：[写实际链接，没有就写"需要去官网核验，搜 [工具名] official"]
- 系统要求：[写实际要求，没有就写"请到官网 System Requirements 页面核验"]
- 费用：[写实际价格，没有就写"当前价格以官网 Pricing 页为准，有免费版但额度有限"]
- 是否需要账号：[是/否/需要什么类型的账号]
- 是否读取本地文件：[是/否/哪类文件]
```

**一定要有的一句话**：
> 这个工具解决不了的事：[写一个工具明确做不到的事，要具体，比如"它不能帮你直接发布内容，生成之后还是要你自己审核和操作"]

---

### 第三幕：我的第一次完整上手记录（400-600 字）

**唯一目的**：让读者觉得"有人帮我走过这段路了"。

**格式要求**：
- 按时间顺序写，每一步都有"我看到了什么"
- 必须有至少 1 个我实际卡住的地方，写清楚卡在哪、怎么解决的
- 必须有 1 个"到这里它开始有用了"的时刻
- 每个关键步骤写：`做什么 → 你会看到什么 → 如果卡住先查哪里`

**卡点写法示例**：
> 第二步我卡了一下——登录进去之后我找不到新建项目的入口，翻了两分钟才发现按钮在右上角，不是主页面的中间。这个不说你可能要浪费时间。

**必须给的内容**：
- 1 段可以直接复制的第一次提示词（针对这个工具的场景，不是通用的）
- 成功的标志（你怎么知道这一步做对了）

**语气规则**：
- 用"第一次"、"当时"、"发现"、"没想到"这类词，保持时间感
- 不要用"接下来我们……"，只写"接下来我……"
- 每 3 步插入 1 句感受：不能全是步骤清单

---

### 第四幕：用了一段时间，我真正在用它做什么（200-300 字）

**唯一目的**：区分"能做"和"真正值得做"。

**格式**：

```
【我现在固定用它做的 2-3 件事】
- 场景 1 + 我的具体用法 + 节省了哪一步（用时间或动作量化）
- 场景 2
- 场景 3（可选）

【我试过但放弃的用法】
- 一个具体的放弃案例 + 原因（这比"它的局限性"更可信）

【我的工作流位置】
- 这个工具在我的流程里处于哪个位置：开始之前 / 过程中 / 结束收尾
- 它取代了我之前用什么
```

**这一幕的核心价值**：诚实地说哪些用法不值得投入，比全说好用更可信。

---

### 第五幕：给同路人的判断框架（150-200 字）

**唯一目的**：给读者一个可以带走的框架，下次看到新工具也能用。

**格式**：
```
如果你是以下三种情况，我的建议：

▶ 完全新手，从来没用过这类工具
→ [具体建议：从哪里开始、预期花多少时间、第一个任务做什么]

▶ 已经在用 AI，想换或加一个工具
→ [具体建议：和已有工具怎么分工、什么场景值得切换]

▶ 时间很少，只想知道值不值得投入精力
→ [直接结论：花多少小时能判断出来、判断标准是什么]
```

**结尾互动问题（固定规则）**：
- 只能有 1 个问题
- 必须是**选择题格式**，读者不需要想很久就能回答
- 问题要引导出下一篇选题

示例：
> 你现在最想让 AI 帮你省掉哪一步？
> A 理解别人的项目或资料
> B 整理和写出自己的内容
> C 写代码或搭工具
> D 每天的重复流程

---

## 标题格式

**优先选这三种格式**：

1. `[工具名] 零基础上手：我卡了一周，整理给你看`
2. `用了 [工具名] 两周之后，我发现它真正有用的地方只有一个`
3. `在你下载 [工具名] 之前，我帮你踩了这些坑`

**禁止的标题格式**：
- `[工具名] 完全使用指南` → 读起来像说明书
- `[工具名] 超强功能大全` → 不可信
- `你不知道的 10 个 [工具名] 技巧` → 凑数感
- `[工具名] 安装配置教程` → 功利但无人味

---

## 声音放大器（具体语句，按需注入）

以下是强制注入"真实感"的句子模板，每篇至少用 **3 句**，不要全部用：

**卡住时**：
- "这一步我第一次没成功，卡了差不多[X分钟]……"
- "这里有个地方教程不会告诉你……"
- "我试了[X]次才发现问题出在……"

**发现时**：
- "用了[X天]之后我才发现……"
- "让我有点意外的是……"
- "我以为它只能[X]，但实际上……"

**诚实时**：
- "说实话，[这个功能]没有我想象的有用……"
- "如果你需要的是[X]，这个工具帮不了你……"
- "根据目前我找到的资料……[待核验的信息]"

**连接读者时**：
- "如果你和我一样[具体特征]，这个值得试……"
- "你可能也遇过这种情况……"
- （禁止用"我们"，只用"你"和"我"）

## 信息密度控制

- **全文字数**：1200-1800 字（低于 1200 说明没有足够细节；高于 1800 考虑拆成系列）
- **段落**：每段不超过 4 行，大段必须拆
- **步骤数量**：超过 7 步必须拆成"先做这件事"和"做完之后"两个部分
- **工具名**：保留英文原名，第一次出现时加中文解释是做什么的
- **单篇原则**：一篇只讲一个工具、一个核心用法，不要在同一篇比较 3 个工具

---

## 系列设计提示（每篇结尾由 AI 输出，不写进正文）

每篇生成后，AI 必须在文章外额外输出：

```
【本篇可以拆出的下一篇】
- 选题 1：[具体标题]
- 选题 2：[具体标题]

【本篇互动问题预期回复类型】
- 如果读者选 A，下篇写：
- 如果读者选 B，下篇写：
```

---

## 硬性禁止（违反则重新生成）

- 正文第一段出现工具介绍（"[工具名]是一款……"）→ 重写开头
- 连续 3 段是步骤，没有插入感受 → 加感受段
- 使用"赋能"、"颠覆"、"范式"、"生态" → 删掉替换
- 结尾超过 1 个互动问题 → 保留最好的那一个
- 编造官方链接、价格、支持系统 → 改成"建议核验"
- 使用"大家"、"我们"、"用户们" → 改成"你"或"我"
- 文章读起来像产品说明书 → 整体重写，回到写作哲学
